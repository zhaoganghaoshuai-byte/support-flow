# 技术支持：故障信息收集与升级流程

本文是项目自编流程，优先级定义仅用于本演示平台。

## 故障信息清单
记录期望行为、实际行为、开始时间、服务与版本、影响范围、可复现步骤、脱敏日志及最近变更。若缺少关键证据应继续追问，不能编造服务监控或已执行的排查结果。

## 工单优先级
urgent：核心服务大范围不可用且无替代方案；high：主要功能受阻；medium：部分功能异常且存在替代路径；low：咨询与小范围改进。初始优先级可由支持工程师根据影响范围调整。

## 工单状态和升级
待处理 open → 处理中 in_progress → 待补充 waiting 或已解决 resolved → 已关闭 closed。等待补充后可回到处理中。已解决问题若仍复现，可重新进入处理中；已关闭工单保持终态。
Agent 只能提出工单草稿；用户在确认页面检查后才正式创建。支持工程师负责分派、状态变更和处理意见，操作记录保留在时间线中。
