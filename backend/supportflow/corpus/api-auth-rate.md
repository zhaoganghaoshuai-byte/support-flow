# API：401、403、429 与有界重试

本文是项目自编教学资料。

## 401 和 403
401 通常表示缺少有效认证信息，检查访问令牌是否过期、Authorization 是否为 Bearer 格式、请求环境是否正确。403 表示当前身份没有执行操作的权限，应核对角色与资源归属。不要通过改传 user_id 绕过服务端授权。

## 429 Too Many Requests
429 表示请求受限。若响应包含 Retry-After，可按服务端要求等待；使用有最大次数和最大等待时间的指数退避，并加入随机抖动。注意按用户或项目维度限制并发。

## 写操作重试与幂等
超时不能证明写入失败。创建工单或订单等写操作应使用稳定幂等键，并先查询已接纳请求的结果。相同键不能用于不同请求内容；数据库唯一约束负责处理并发创建，避免网络重试导致重复记录。
